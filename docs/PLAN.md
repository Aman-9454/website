11. ✅ Footer wave + CTA heading scale, then a real cross-browser animation bug found and fixed:

    - **Debugging note, in case this resurfaces:** the owner reported the footer wave and CTA converge-node "don't animate" in their own dev environment, while every automated check from this session (including fresh Playwright runs against their actual live `localhost:3000`) showed it working. Root-caused two real, separate bugs rather than assuming it was environmental:
      1. All three canvas scenes gated their animation loop on an `IntersectionObserver` reporting `isIntersecting`. That's a reasonable optimization (don't animate off-screen content) but it's also one more thing that can silently never fire `true` in an unusual host — an embedded webview, a privacy/content-blocking extension — leaving the canvas permanently frozen with zero console error. Removed it from all three (`useDeferredMount`, `AnimatedGlyphSphere`, `AnimatedWave`) in favor of just `document.hidden`/`visibilitychange` (pause only when the tab itself is backgrounded) — simpler, fewer failure modes, negligible perf cost for small decorative scenes.
      2. Separately, both canvas components sized their backing store once via `window.addEventListener("resize", ...)`, which misses the canvas's own box changing size for any other reason (web fonts loading in, layout settling right after mount) — confirmed via screenshot this caused the footer wave to render only across part of its width. Fixed with a `ResizeObserver` on the canvas element itself.
      3. Also gave `CTAVisual` a permanent CSS-only fallback (a static radial-gradient glow, `color-mix` on `--foreground`) so there's never a bare void behind the button regardless of WebGL/tier detection — the WebGL scene crossfades on top of it once ready.
    - Verified the fix wasn't just "looks plausible" — screenshotted the same canvas region twice ~1.5s apart and confirmed the pixels actually differ (genuinely animating), against the owner's real running dev server, not a separate build.
